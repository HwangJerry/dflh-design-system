# 현재 비밀번호 오답 — Android 실기기 재검증

**2026-10-11 현재 검수한 앱에서 IOS-AUTH-01은 iOS에 재현됐으며 Android에서는 재현되지 않았다.** 기존 검수 기록만 인용하지 않고 연결된 Galaxy에서 같은 입력 오류를 다시 제출해 UI·앱 재실행·운영 서버 요청을 대조했다. 다른 인증 결함이 모두 없다는 판정은 아니다.

## 대상과 방법

- Galaxy Note9 SM-N960N, Android10, 기기279b4638fc217ece.
- 설치 앱 com.dflh.saf.v2, release1.3.3/build1. 실제 설치 APK를 추출해 검증 release와 SHA256 `fb7687fe85a41fa29edd13685254243917d6153705966c9892e621d2d09d2b3e` 일치를 확인했다. 검사 후 설치 APK도 동일했다.
- 승인된 QA **12829 / AndroidAudit2610A / AndroidAuthQA**, Native+Kakao 연결. 기존에 새로 생성·변경한 QA 비밀번호를 비공개 파일에서 사용했다. 원래 개인/root 비밀번호와 기기 인증 토큰은 읽지 않았다.
- 운영 c3 서버. 제품 코드·앱 설치·DB·환경·SMS 설정 변경0. 앱 삭제·데이터 초기화0.
- root가 Android UI를 직접 조작하고 별도 agent가 서버를 읽기 전용 관찰했다. 다른 agent가 소스와 APK 출처를 독립 검토했다. iPhone 조작은 없었다.

로그인 → 앱 force-stop·재실행 → 동일 회원 내정보 확인 → 잘못된 현재 비밀번호와 유효한 새 생성 비밀번호/확인 입력 → 최종 ‘변경’ 버튼1회 → 오류·로그인 유지 → 다시 force-stop·재실행 → 동일 회원 복원 → 현재 기기 표준 로그아웃·재실행 순서로 검사했다. 새 비밀번호 후보는 정상 현재 비밀번호와 다르게 생성했으며 올바른 현재 비밀번호로 변경 제출한 적은 없다.

## iOS와 다른 이유

| 현재 비밀번호 오답 | iOS 최신 실기기 | Android 이번 실기기 |
|---|---|---|
| 비밀번호 변경 요청 | 401 2회 | 401 1회 |
| 토큰 갱신 | 200 1회 | 0회 |
| 앱 로그인 | 종료됨 | 유지됨 |
| 서버 세션 | 앱은 로그아웃됐지만 활성 세션이 남음 | 로그인 유지 상태와 일치하는 동일 세션 유지 |

Android DflhApiClient는 WRONG_PASSWORD401을 토큰 만료 처리에서 제외해 refresh·재요청하지 않는다. ProfileViewModel은 입력 오류를 표시하고 로그인 상태를 유지한다. iOS APIClient는 이 오류도 갱신 대상으로 처리하고 재요청401에서 로컬 인증 상태를 지워 이번 결함을 만들었다. iOS 제품 수정은 아직 수행하지 않았다.

이 판정은 현재 비밀번호 오답의 동일 시나리오에 대한 것이다. Android의 일반401 안내까지 서버 code별로 완성됐다는 의미는 아니다. 실제 토큰 만료·네트워크 실패 등의 검증 범위를 이번 결과에 새로 합산하지 않는다.

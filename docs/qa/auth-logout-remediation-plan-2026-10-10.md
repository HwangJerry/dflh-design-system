# Android 로그아웃 보완 및 양 플랫폼 검증 계획

작성일: 2026-10-10. 상태: Android 코드 보완·정식 Gradle 빌드·단위 테스트·Kakao R8·갤럭시 검수 완료. iOS 신규 회귀와 탈퇴 최종 완료는 후속 범위. [구현 결과](auth-local-first-logout-implementation-2026-10-10.md) 참조.

기준 소스: Android `main/00b8f26`, iOS `main/c0bb5c0`, 서버 `main/d1fdfed`.

## 목표와 범위

로그아웃 확정 후에는 네트워크 응답을 기다리지 않고 기기의 인증 정보를 안전하게 삭제하고 로그인 화면으로 전환한다. 서버 정리는 이전 세션의 정리 정보로 수행한다. 앱 종료·재실행, 오프라인, 새 로그인과의 경합에서도 이전 로그인 복원이나 새 세션 삭제가 발생하지 않아야 한다.

Android의 화면·인증 저장소·재시도 큐·API 연결을 보완한다. iOS는 현재 처리 순서를 기준으로 회귀 검증한다. 서버의 기존 계약을 활용하며, 새 운영 migration은 현재 계획에 필요하지 않다. 실제 배포 계약 확인 결과에 따라 배포 필요 여부를 판단한다. 정기 결제는 제외한다.

## 1. RED: 현재 결함을 실제 호출 경로의 테스트로 고정

현재 `MainActivity.signOutWithPushUnregister`는 푸시 요청 후 `SessionViewModel.signOut`을 호출한다. 푸시 응답을 무기한 보류하는 제어 가능한 의존성을 두고, 사용자 로그아웃 확정이 실제 앱에서 사용하는 진입점으로 전달되도록 테스트한다.

- 푸시 응답 전 기기 토큰이 삭제되고 `SignedOut`이 되어야 한다는 검증을 먼저 실패시킨다.
- 계정 A의 정리가 보류된 중 계정 B로 로그인한 뒤 A의 정리를 완료해도 B가 유지되어야 한다는 검증을 추가한다.
- 로그아웃 확정과 취소를 구분한다. 취소는 인증 정보와 푸시 등록을 그대로 보존한다.
- 테스트용 콜백을 별도로 복제하지 않는다. 추출할 경우 실제 앱도 사용하는 로그아웃 진입점으로 만들고 화면 연결까지 검증한다.

완료 기준: 지연 결함으로 인한 RED를 확인하고, Android 하위 Repository만 검증하는 기존 테스트의 사각지대를 해소한다.

## 2. GREEN: 기기 로그아웃을 먼저 완료

`MainActivity`의 네트워크 선행 처리를 제거하고 로그아웃 요청을 인증 계층에 위임한다. `SessionViewModel`과 `SessionRepository`는 다음 순서를 보장한다.

1. 원래 세션의 인증 정보와 현재 기기의 푸시 토큰을 정리용으로 캡처한다.
2. 암호화 저장소에 정리 요청 저장과 활성 로그인 삭제를 같은 커밋으로 처리한다.
3. 메모리 토큰과 진행 중 인증 작업을 무효화하고 `SignedOut`을 발행한다.
4. 화면 수명과 독립적인 앱 범위에서 이전 세션의 서버 정리를 시작한다.

일반 로그인 상태뿐 아니라 승인 대기·반려·세션 복원 실패 화면의 로그아웃/다른 계정 로그인 진입점도 같은 경로를 사용한다. 저장된 푸시 토큰 유무가 로컬 로그아웃 완료 시점에 영향을 주지 않아야 한다.

저장소 커밋 실패를 성공으로 숨기지 않도록 결과를 확인한다. 저장 실패 시 메모리 정리, 재시도 정보 보관과 사용자 안내를 구분하고, 디스크 삭제가 확인되지 않으면 재실행까지 안전한 로그아웃이라고 판정하지 않는다. 정리용 인증 정보는 다시 로그인 상태로 복원하지 않는다.

완료 기준: 제어된 푸시 요청이 끝나지 않아도 RED 테스트가 통과하며, 정상 저장 상황에서 정리 정보와 활성 로그인 삭제가 함께 영속화된다.

## 3. 이전 세션에 한정한 서버·푸시 정리

Refresh 토큰이 있으면 기존 `POST /api/auth/logout/deferred`를 사용한다.

- 본문에 캡처한 `refreshToken`과 선택적인 `deviceToken`을 전달한다.
- 현재 로그인 Authorization 헤더 및 자동 refresh/401 재시도를 사용하지 않는다.
- `204`와 `X-Session-Logout-Result: confirmed`를 함께 확인했을 때만 서버 종료 확인으로 판정한다.
- `unconfirmed`, 헤더 누락, 만료/잘못된 증명은 서버 종료를 확인하지 못한 결과로 구분한다. 통신 실패·429·5xx는 원래 증명의 유효기간 안에서 재시도한다.
- 새 로그인 토큰이나 새 푸시 등록에 이전 정리 요청이 적용되지 않도록 원래 계정·세션에 대한 서버 제한을 유지한다.

이 계약은 서버가 원래 세션과 해당 기기의 푸시 등록을 함께 정리하므로 Android의 별도 푸시 해제 선행 요청을 제거할 수 있다. Access 토큰만 있는 기존 세션은 캡처한 토큰으로 한정된 정리 경로를 두고, 만료 후 결과를 확인된 종료로 표시하지 않는다.

`AuthApi`와 `DflhApiClient`는 응답 상태·확인 헤더를 검증할 수 있도록 필요한 범위만 확장한다. 기존 API의 성공/오류 처리에는 영향을 주지 않도록 테스트한다.

현재 Android에는 전체 기기 로그아웃 기능이 없으므로 새 기능을 추가하지 않는다. iOS 전체 기기 로그아웃은 기존 일회성 요청 및 새 로그인 보호 동작을 회귀 검증한다.

완료 기준: Access 만료 상태에서도 새로운 로그인 세션을 발급하지 않고 이전 세션을 정리하며, 명시적 서버 확인과 미확인을 구분한다.

## 4. 재시도·경합 검증과 REFACTOR

기존 `LogoutRetryOutbox`를 확장하고 암호화 저장 형식을 호환되게 유지한다. 필요한 경우 기존 v1 항목을 정리용 항목으로 변환한다. 기존 기록에는 푸시 토큰이 없을 수 있으므로 다른 회원의 현재 토큰을 끌어다 채우지 않는다.

| 상황 | 검증할 결과 |
| --- | --- |
| 정상 온라인 로그아웃 | 기기 즉시 종료, 서버 세션 종료 확인, 원래 푸시 등록 정리 |
| 푸시/서버 요청 지연 | 요청 완료 전 로그인 정보 삭제와 로그인 화면 전환 |
| 오프라인 로그아웃 후 앱 종료 | 재실행해도 로그아웃 유지, 정리 기록 보존 |
| 온라인 복구 | 같은 이전 세션만 재시도하고 성공 후 기록 제거 |
| A 로그아웃 직후 B 로그인 | A의 늦은 완료·401·재시도가 B를 삭제하지 않음 |
| 같은 회원 재로그인·푸시 재등록 | 이전 SID 정리가 새 SID의 등록을 삭제하지 않음 |
| Access 만료·Refresh 유효 | Refresh 발급 없이 기존 증명으로 종료 |
| 응답 유실 후 재시도 | 원래 세션 범위의 중복 정리가 안전함 |
| 반복 탭·중복 복구 이벤트 | 중복 작업이 새 세션을 건드리지 않음 |
| 저장 실패·증명 만료·확인 헤더 누락 | 확인된 서버 종료로 오인하지 않음 |
| 이전 재시도 기록이 남은 앱 업데이트 | 기존 기록이 유실되거나 로그인으로 복원되지 않음 |
| 푸시 토큰 없음·권한 거부·토큰 변경 | 로컬 로그아웃 정상 완료, 캡처한 소유권만 정리 |

동작이 통과한 뒤 책임을 정리한다. 화면은 요청과 표시, 인증 계층은 캡처·로컬 종료, 재시도 큐는 영속화·서버 정리를 담당한다. 토큰·자격 증명은 로그에 출력하지 않는다.

## 5. 빌드·서버 계약·iOS 회귀 검증

- Android 관련 인증 테스트와 `./gradlew :app:testDebugUnitTest :app:assembleDebug`를 실행한다.
- 배포 후보는 minified release 빌드와 기존 Kakao R8 검사를 통과시킨다.
- 서버의 기존 deferred logout·명시적 확인·푸시 소유권 테스트를 실행한다. 정상 DB 커밋, 롤백, 만료 경계, 이전/새 SID 경합은 일회용 MariaDB 통합 환경에서 확인한다.
- iOS에서 정상/오프라인 로그아웃, 이전 정리 중 새 로그인, 만료된 Access, 전체 기기 로그아웃의 회귀 테스트를 실행한다. 새 테스트에서 결함이 확인된 경우 해당 부분을 추가 수정한다.
- 운영 API와 migration 085의 실제 적용 상태를 읽기 전용으로 확인한 뒤 실기기 검수를 진행한다. 확인되지 않은 배포 상태를 적용 완료로 가정하지 않는다.
- Android 문서에 남아 있는 “서버 로그아웃 후 로컬 삭제” 설명을 실제 동작과 일치하도록 갱신한다.

## 6. 실기기 QA와 완료 판정

두 기기는 기존에 확인된 서로 다른 QA 계정을 사용한다. 기존 실제 사용 계정의 비밀번호를 읽거나 다른 기기의 계정을 삭제하지 않는다.

Android에서 ID/PW·카카오 각각 정상 로그아웃, 네트워크 지연, 비행기 모드 중 로그아웃을 검수한다. **로그아웃 화면 전환 후 서버 정리가 아직 진행 중인 시점에 강제 종료하고 재실행**하여 자동 로그인이 되지 않는지 확인한다. 화면 전환·토큰 삭제·재시도 보존을 단계별로 기록한다. 실제 지연 구간을 통제한 테스트와 기기에서 수행한 검수를 구분한다.

다시 연결한 뒤 원래 세션과 푸시 등록만 정리됐는지 서버에서 대조한다. 같은 기기에서 다른 QA 계정 로그인 및 같은 계정 재로그인·푸시 재등록을 수행하고, 늦은 이전 정리가 새 로그인을 보존하는지 확인한다. 정상 로그아웃된 Android가 다른 기기의 유효 세션을 종료하지 않는지도 확인한다.

iOS는 정상/오프라인 로그아웃과 cold restart, 서버 정리 중 재로그인을 대조 검수한다. 실제 푸시 전달은 사용 가능한 QA 발송 경로가 있을 때 별도로 확인하며, 이미 제공자에 인계된 알림을 회수하는 기능으로 판정하지 않는다.

완료 기준은 코드 테스트·빌드 통과, Android 강제 종료 후 로그아웃 유지, 원래 세션의 서버 정리 확인, 새 세션과 다른 기기 보존이다. 실기기 증거가 없으면 코드 검증 완료와 실기기 검수 미완료를 구분해 보고한다.

실행 권한 복구 후 ADB·SSH 접근과 Gradle 빌드를 완료했다. Android의 수정 release 검수 및 로컬 제어 서버를 사용한 실제 화면 지연/재로그인 검수는 [기기 QA 보고서](android-local-first-logout-device-2026-10-10.md)에 기록한다. iOS는 사용자의 중단 요청에 따라 이번 작업에서 조작하지 않았다. Android 탈퇴 요청 24·25·26의 최종 완료 확인과 실제 푸시 전달은 별도 후속 항목으로 유지한다.

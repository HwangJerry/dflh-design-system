## 추가 확인이 필요한 범위

1. 최신 APK에서 기존 QA 회원 탈퇴 후 실제 카카오 신규 가입 전체 성공·승인·재로그인. 기존 APK의 성공 기록과 이번 최신 APK 결과를 구분한다.
2. 신규 Native의 탈퇴·관리자 처리 회귀. 승인 이후 비밀번호 변경·정상 복원·서버 세션 철회 후 복원 거부는 추가 통과했다.
3. 탈퇴 최종 completed 및 실제 완료 화면. 운영 데이터 삭제와 전체 처리 완료는 다르다. 기존 요청24/26의 SMS 정리 예상은10월11일01:36:29KST, 요청25는02:34:58KST이며 정상 worker 결과를 기한 이후 확인해야 한다. 기한이나 상태를 강제로 변경하지 않는다.
4. 최신 APK의 access/refresh 만료 대기, post-commit·처리중·불확실 응답 화면. 실제 Talk 동의 취소 및 서버에서 철회한 세션의 복원 거부는 이번 실기기로 확인했다. 기존 실기기·단위·서버 계약 근거를 현재 기기의 장애 재현 결과와 혼동하지 않는다.
5. 서비스 세션 정리와 별개로 Kakao SDK의 앱별 제공자 토큰 캐시를 지우는 정책·실행 검증. KakaoTalk 계정 자체의 로그아웃 요구는 없다. 캐시 원문·유효성을 추출하지 않아 잔존·악용 결함으로 단정하지 않는다.
6. 로그아웃·탈퇴 이후 실제 푸시 미전달. 서버 기기 등록0 확인은 실제 배송까지 증명하지 않는다.

비밀번호 변경 성공 시 현재/다른 기존 세션을 유지하는 구현은 소스에서 확인했다. 모든 기기를 종료한다는 제품 정책은 확인되지 않아 기존 요구 위반으로 집계하지 않는다. 비밀번호 찾기는 verified EMAIL 기반이며 이번 LOCAL_USERNAME QA 회원의 SMS 고정 코드로 재설정할 수 없다. 임의 인증수단·reset token을 운영 DB에 추가하지 않았다. 복원 거부 검수는 표준 전체 로그아웃 API로 정확히 수행했다.

## 독립 자동 검증

- 선행 최신 Android 전체 단위685통과·실패0, 실제 Keystore 계측2통과. 이번 인증 부분집합195개는685개의 부분집합이다.
- 신규 늦은 로그인 응답 회귀: 정상 대조와 현상 관찰2통과, 요구 계약1RED. 기존685개 실패라는 뜻이 아니다.
- 비밀번호 변경 비즈니스401의 refresh 성공·통신 실패·refresh 거부3분기 독립 검사3통과. 현재 동작 관찰 검사이며 개선 완료를 의미하지 않는다.
- 서버 단위·계약101통과, 실제 HTTP/MariaDB56통과, 전화번호 소유권 경합1통과, 기존 migration 승인 계약3통과. 범위가 중복되므로 합산하지 않는다.
- 비밀번호 정책의 격리 HTTP/DB 관찰4통과: 잘못된 현재 비밀번호에서 세션 유지, 정상 변경에서 기존2가족 유지, LOCAL 회원의 EMAIL 재설정 권한 부재, 합성 EMAIL reset 후 기존2가족 인증·refresh 거부 및 새 비밀번호 로그인. 운영 인증수단이나 token을 삽입하지 않았다.
- DB 통합 첫 실행의 하네스 시간 제한은 격리 복제에서만15초→90초로 변경했다. 제품 assertion·운영 DB·제품 소스는 변경하지 않았다.

## 관리자 단계와 임시 설정

Computer Use가 Chrome 접근을 `Computer Use was not approved to use Google Chrome`으로 거부한다. 사용자에게 실제 QA 회원의 승인·탈퇴 요청 조기 처리를 요청했고, DB 쓰기나 Chrome 인증정보 추출로 우회하지 않는다.12829 승인 및12827 요청31 조기 처리는 사용자 완료 답변을 받았다. 요청31은 제공자 해제 outbox DELIVERED 후 정상 worker 재시도로 DB 삭제까지 확인했지만 최종 완료는 아니다.12829의 요청32 조기 처리를 사용자에게 요청했다.

추가 Android 전용 SMS 테스트 번호는 기존 두 번호·고정 코드·개인정보 동의 버전을 보존한 채 임시 추가했다. 요청32 관리자 처리를 기다리며 원래 설정으로 복구했고 서버 재시작 성공·기존 번호/고정 코드/동의 버전의 정확한 보존을 확인했다. `sms-setting-state.json`은 restoreRequired=false·originalPhonesRestored=true다. 후속 카카오 가입 검수에 필요한 기간에만 다시 적용한다. 재시작 후 실제 worker 환경·서버 health의 독립 관측은 서버 담당 최종 기록을 따른다.

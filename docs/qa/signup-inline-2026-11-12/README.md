# 가입 화면·사진 업로드 추가 검증 (2026-11-12)

## 원인과 수정

운영의 `/api/auth/social/link/photo` 요청은 22:43에 HTTP 400으로 거절됐다. 앱과 업로드 처리기는 5 MiB를 허용하지만 상위 API 미들웨어는 2 MiB로 제한했다. 동일한 토큰 오류 입력에 대해 1 KiB 파일은 INVALID_TOKEN(404), 3 MiB 파일은 FILE_TOO_LARGE(400)로 갈렸다. 이는 앞서 고친 폴더 권한 문제와 별개다.

업로드 POST 경로만 5 MiB 파일 + 64 KiB multipart 여유로 변경했다. 실제 파일은 여전히 5 MiB 이하를 강제하고 다른 API는 2 MiB를 유지한다. 수정 후 운영의 3 MiB 요청은 토큰 검사까지 진행(404)하고 5 MiB 초과는 계속 400으로 차단된다. 이 음성 토큰 검사는 인증을 우회하거나 업로드 성공으로 간주하지 않는다.

실제 MariaDB·파일 저장소 통합 테스트는 2 MiB 초과 실제 PNG 저장과 소셜 가입 토큰의 사진 연결, 최종 가입 사진 반영, 미사용 사진만 정리됨을 확인했다. 운영에서는 별도 심사용 계정에 작은 실제 이미지를 저장하고 공개 URL 원본 바이트 일치를 확인했다. 실사용자의 대용량 사진 선택부터 운영 소셜 가입 완료까지는 별도 증거다.

Android는 상대 업로드 경로 `/uploads/...`를 Coil에 그대로 넘기던 표시 오류도 수정했다. 앱의 실제 백엔드 원점으로 해석해 미리보기를 표시한다.

## 화면 계약

- iOS/Android: 가입 첫 필드부터 검토까지 상단 원형 사진과 편집 배지 유지. 별도 사진 단계·사진 텍스트 카드·사진 사용 확인 페이지 제거.
- 사진은 같은 자리에서 시스템 선택기를 열고 돌아와 업로드 상태와 실패를 표시한다. 이전 사진·다른 입력은 유지한다.
- 발송 후 단일 입력 옆 버튼: 0자리 재발송 활성 / 1~5자리 확인 비활성 / 6자리 확인 활성. 별도 재발송 텍스트 링크 제거.
- iOS: 발송·확인 중 번호 수정 후 늦게 도착한 응답 무시, 재발송 실패 후 기존 코드 사용 유지. 각 회귀는 수정 전 실패·수정 후 통과를 재현했다.

## 검증

- iOS: 단위 테스트 748개 통과. 시뮬레이터 빌드 통과. 최종 화면 결과는 아래 추가 기록.
- Android: 가입·인증 단위/Compose 테스트 203개 통과. 테스트 APK 빌드 통과. URL 표시 회귀 포함. 최종 기기 화면 결과는 아래 추가 기록.
- 운영 가입 API: iOS/Android 클라이언트 헤더별 로그인, canonical pending, ID/전화/이메일 재가입 안내, 유효한 전화 인증 후 중복 등록의 SIGNUP_ALREADY_PENDING, 세션 로그아웃 등 16개 검사 통과.
- iOS/Android 디자인 시스템 및 계약 문서 검사 통과.
- 전체 Android 추가 실행의 12개 실패는 비가입 피드 테스트 임시 디렉터리 생성 시 디스크 부족이었다. 이를 제품 오류나 테스트 통과로 간주하지 않았다. iOS 첫 화면 실행은 디스크 부족 이후 runner 준비 중 abort되어 재실행했다.

공통 규칙: `../06_metanoia-lab/malfunctionroom-design-system/patterns/flows.md`의 ‘회원가입 입력 흐름’ 및 해당 작업공간 `AGENTS.md`에 반영했다.

## 화면 검증 추가 결과

- iOS: 실제 iOS 27.2 시뮬레이터 XCUITest 3개 통과(가입 순차 입력과 편집, 0·1·5·6자리 버튼, 인증 후 입력 숨김/번호 수정 후 재인증, 상단 사진, 실패 후 검토 유지, 승인 대기 다이얼로그). 가로 화면 테스트 1개도 별도로 통과했다.
- Android: 상단 사진을 더한 상태에서 키보드가 켜지면 CTA가 밀려나는 문제를 실제 화면 테스트로 발견했다. 입력 노드를 재생성하지 않고 키보드 표시 시 헤더의 설명·진행 표시 공간만 축소하도록 수정했다. 최종 재실행은 통과했으며 결과는 뒤에 기록한다.

- Android 최종 에뮬레이터 테스트 통과: 키보드를 켠 상태의 첫 입력→전화→문자 요청→0/1/5/6자리 버튼→인증 입력 숨김→이메일→이름·전화 수정→기수·학과·졸업연도→사진 전용 페이지 없이 검토→동의→최종 제출 콜백. 테스트의 CTA에 실제 표시 여부도 검증한다. 키보드 배치 수정 전·후 화면은 `android/`에 보관했다. 가입 전체 통과 증거는 테스트 결과로 구분한다.

운영 저장 처리기의 `UPLOAD_MAX_FILE_SIZE_MB`는 10(default)임도 확인했다. 추가 저장 제한 2 MiB가 있었던 것이 아니라 API 공통 제한과 5 MiB 클라이언트/업로드 처리기 계약의 충돌이었다.

통과 항목은 해당 테스트 환경과 범위에 대한 증거다. 실제 외부 카카오 로그인·일반 전화의 통신사 SMS 수신·실사용자 사진의 사진 앱 선택부터 운영 가입 완료까지의 전 과정을 대신하지 않는다. 운영 API 검사는 지정된 합성 테스트 전화와 별도 QA 계정으로 수행했고, 화면 검사는 명시적 테스트 응답을 사용했다.

# Android·iOS 인증 재검토

검토 시각: 2026-10-10 18:03–18:06 KST.

**Android 수정 코드 미통합 문제는 해결됐다. Android 로그아웃 지연 결함은 남아 있다. iOS는 이번 소스 검토에서 추가로 확정한 인증 결함이 없다.** 실기기 재실행과 운영 서버 조회는 현재 세션의 접근 제한으로 수행하지 못했다.

## 현재 코드와 이전 판정의 변경

| 대상 | 현재 코드 | 재검토 결과 |
| --- | --- | --- |
| Android | `main`, `00b8f26af7b20d6aefd7971d0f8eade3acf25f28` | 17:48 KST에 동문 필터와 인증 수정 통합. `c0490c3` 포함 확인 |
| iOS | `main`, `c0bb5c0eb843eac90f1a47e73a44b7564b35ae25` | 이전 최종 검수 코드와 동일 |
| 서버 | `main`, `d1fdfed` | `464ddda` 이후 변경은 로그인 오류 문구 golden fixture 한 곳. 인증 실행 코드 동일 |

Android의 `core/auth`, `core/network`, `feature/auth`, `feature/login`은 기존 검수 후보 `c0490c3`와 차이가 없다. 따라서 오전 보고서의 **“현재 개발 브랜치에 수정 코드가 없다”는 판정은 현재 시점에 해소됐다.** 이 확인은 소스 통합 확인이며 기기에 설치된 APK나 배포 앱의 버전 확인을 대신하지 않는다.

제품 저장소의 추적 파일은 이번 검토에서 수정하지 않았다. 기존 미추적 QA 파일도 유지했다.

## 확정된 잔여 결함: Android 로그아웃 순서

우선순위 P1. 현재 `dflh-saf-v2-kotlin/app/src/main/kotlin/com/dflh/app/MainActivity.kt:581`의 `signOutWithPushUnregister`는 다음 순서로 실행된다.

1. 저장된 푸시 토큰으로 서버 푸시 등록 해제 요청을 기다린다.
2. 요청이 종료된 후 `onSignOut()`을 호출한다.
3. 그때부터 `SessionRepository.signOut()`이 재시도 정보를 저장하고 기기의 인증 정보를 지운다.

푸시 토큰이 있고 요청이 지연되는 동안에는 사용자가 로그아웃을 확정해도 기기의 로그인 정보가 남는다. 이 구간에서 앱 프로세스가 종료되면 재실행 시 기존 로그인 정보가 복원될 수 있다. 실제 프로세스 종료를 이번에 기기로 재현한 것은 아니며, 지연 원인과 호출 순서는 현재 소스와 아래 진단으로 확인했다.

**현재 main의 실제 콜백 본문을 추출하여**, 푸시 요청이 멈춘 상태를 제어한 Kotlin 코루틴 진단을 다시 실행했다.

```text
localLogoutBlockedUntilPushCompletes=true
localLogoutAfterPushCompletion=true
```

하위 Repository는 이미 로컬 인증 정보를 먼저 지우지만 UI가 그 Repository에 도달하기 전에 기다리므로 결함이 남는다. 수정 시 원래 세션과 푸시 정리 정보를 안전하게 저장하고 로컬 로그인 상태를 먼저 종료한 뒤, 원래 세션에 한정하여 서버·푸시 정리를 진행해야 한다. 단순히 두 호출만 뒤집으면 현재 로그인 토큰에 의존하는 푸시 요청이 실패할 수 있으므로 이전 세션의 소유권도 함께 다뤄야 한다.

## iOS와 소셜 가입

iOS `AppState.signOut`은 정리 정보 저장·기기 인증 정보 삭제·로그아웃 화면 전환 후 네트워크 정리를 수행한다. 서버 종료는 명시적인 `confirmed` 응답을 요구한다. 이번에 확인한 현재 소스는 기존 최종 검수 코드와 동일하며 새로 확정한 인증 결함은 없다.

기존 iOS 전체 테스트 **716개 통과**와 실기기 카카오·Apple·ID/PW 검수 근거는 유지된다. 이번에 iPhone에서 다시 실행한 결과는 아니다. 실제 iOS SMS 수신/자동 입력 및 실제 푸시 전달 차단은 여전히 별도 실기기 확인이 필요하다.

Android 카카오 어댑터는 카카오톡 사용 가능 시 앱 인증부터 시도하고, 제한된 오류에서만 웹 인증으로 전환하는 구현을 유지한다. 이번에는 실제 앱 리다이렉트를 재실행하지 못했다.

기존 회원이 소셜 연결을 해제한 뒤 같은 소셜 계정으로 새 가입을 시도하면, 가입 양식에 진입한 후 최종 제출에서 기존 소유권 충돌을 안내하는 Android UX 개선 사항은 남아 있다. 기존 회원에게 소셜 계정 소유권을 유지하는 정책은 정상이며, 개선 방향은 가입 시작 시 기존 ID/PW 로그인·재연결을 안내하는 것이다. iOS의 같은 화면 동작은 이번에 재현하지 않았다.

## 아직 확인하지 못한 범위

- Android ADB는 로컬 소켓 생성이 `Operation not permitted`로 거부됐다. 연결 해제를 의미하는 결과가 아니다.
- iOS CoreDevice 기기 조회는 15초 제한에서 타임아웃됐다.
- 운영 SSH 연결도 `Operation not permitted`로 거부됐다. 실제 배포 버전과 현재 DB 상태를 재확인하지 못했다.
- Android 탈퇴 요청 24·25·26의 마지막 서버 확인은 여전히 01:35:54 KST다. 당시 남은 SMS 보관 정리 예상은 **10월 11일 01:36–02:35 KST**였으며, 현재 상태·최종 완료는 새로 확인하지 않았다.
- 기존 탈퇴 모니터 출력은 갱신되지 않았다. 모니터 정상 실행을 주장하지 않는다. 또한 별도 iOS QA가 정상 탈퇴한 회원을 반드시 보존하도록 가정한 검증 조건은 재사용 전 수정이 필요하다.

따라서 **“양쪽 인증 검수와 탈퇴 처리가 모두 끝났다”는 판정은 아직 할 수 없다.** 우선 Android 로그아웃 순서를 수정하고, 수정 APK에서 느린 푸시 요청 중 강제 종료·재실행을 검수해야 한다. 그 뒤 최신 설치 앱의 카카오 앱 전환, 회원 가입 취소/실패 후 세션, 계정 전환과 로그아웃 후 푸시, Android 탈퇴 최종 완료를 다시 확인해야 한다.

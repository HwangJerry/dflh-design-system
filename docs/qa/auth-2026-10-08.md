## 기능 구조 및 기대 동작

| 구간 | 구현 및 검수 기준 |
| --- | --- |

청구키가 없는 failed/pending 구독 참조가 원본 iPhone 계정의 완전 삭제를 막는 구현 공백도 확인했다(AUTH-QA-10). 실제 구독 2건은 failed 1건, pending 1건이며 저장 청구키는 0건이다. 삭제 목록에 SUBSCRIPTION 처리가 없고 표준 관리 취소도 참조를 제거하지 않는다. pending 결제 진행 여부 판정과 검증된 실패·취소 기록 정리가 필요하다. 기부 보존 근거 및 파일 소유권 검토 자체는 정당한 보류 항목으로 구분한다. iOS 중단 요청 이후 이 문제의 운영 처리는 사용자에게 인계했다.

AUTH-QA-11(Android 신규 QA 회원의 관리자 조기 탈퇴): preview는 보류 0건·13건 계획으로 표시되었지만 DB 삭제 뒤 `other_identifiers / EXTERNAL_ERASURE_PENDING`으로 멈췄다. 읽기 전용 전체 text-column 검색에서 기존 Android 전화번호/이메일의 잔류값은 `ALUMNI_PHONE_VERIFICATION.PHONE` 2건이었다. 이 테이블은 삭제 계획에 포함되지 않고 별도 24시간 보관·정리 정책을 사용한다. 따라서 미리보기와 실제 완료 조건이 다르다. 회원·identity·phone claim·소셜 연결·공급자 credential은 0건이며, 이를 전체 탈퇴 완료로 기록하지 않는다. 동일 전화번호로 새 회원 12816의 정상 재가입도 가능했다. 이전 요청의 간접 식별값 검색은 새 회원의 WEO_MEMBER/AUTH_PHONE_CLAIM까지 구분 없이 검색하므로, 정당한 재가입 기록이 이전 탈퇴 완료를 막는 추가 위험이 있다. 이 위험의 단독 기여는 기존 SMS 잔류와 분리해 실기기에서 검증하지 않았다. 새 회원은 기존 삭제 작업의 DB 처리 대상이 아님을 stage 및 소스에서 확인했다.

AUTH-QA-12(Android 실기기 / backend 공통, P1): ID/PW 회원 12816에 Kakao 연결이 성공했고 LOCAL_USERNAME/KAKAO ACTIVE 및 기존 회원 정보 보존을 확인했다. 연결 해제는 성공했지만 같은 계정에 다시 연결하면 실패한다. 재시작 뒤 재시도 포함 실기기 2회 재현했다. 해제 후 canonical KAKAO identity는 REVOKED로 남고 legacy 연결은 0건이다. 운영 로그에서 같은 회원의 재연결 실패가 `social identity collision without an active connection` 및 `UQ_AUTH_IDENTITY_PROVIDER_SUBJECT` 중복으로 확인됐다. `insertSocialIdentityTx`는 재활성화 없이 INSERT만 수행한다. 별도 합성 MariaDB의 동일 연결→해제→재연결 probe도 같은 1062 충돌로 실패했고, 최초 연결·해제·ID/PW 로그인 통제 단계는 통과했다. 정상 재인증 대기 안내가 아니라 연결 해제→재연결 경로의 서버 결함이다. 예상 실패 probe는 `docs/qa/auth-20261008/SocialRelinkProbe_test.go` 및 별도 backend QA worktree에 보관하고 기본 테스트 경로와 임시 schema timeout은 원복했다.

AUTH-QA-13(Android 설치 앱 / P3): 탈퇴 안내는 처리 전 앱에서 취소 가능하다고 설명하지만 최종 확인 sheet는 “앱에서 취소할 수 없습니다”라고 표시한다. 요청 후 로그인 차단 안내는 다시 취소 가능하다고 설명한다. 실기기 요청 16 및 `AccountDeletionScreen.kt`의 동일 문구에서 확인했다. 조기 실행이 시작되기 전 실제 접수증 처리 현황에도 탈퇴 신청 취소 버튼이 표시됐다. 이전 요청 12의 실제 취소 성공과 별개인 안내 불일치이며, 취소 API 실패로 집계하지 않는다.

소스 probe 결과: Android **8개 중 6개 실패 / 2개 통제 사례 통과**, iOS **7개 중 6개 테스트 실패 / 1개 통제 사례 통과**(실패 assertion 9개). 같은 원인을 중복 결함 수로 부풀리지 않았다. 예상 실패 probe는 기본 테스트 디렉터리에 남겨 두지 않고 아래 문서 파일로 보관한다.

## 계획 변경 후 Android 직접 QA

주 세션이 실기기 및 관리자 Computer Use를 직접 사용했다. 새 Kakao 회원 12814의 승인 대기·승인·로그아웃·재로그인을 검수한 뒤 요청 15로 DB 삭제를 진행했다. 이어 실제 SMS 확인으로 ID/PW 회원 12816(AuthQANativeAndroid)을 가입했다. 필수 동의 전 제출은 차단됐으며 DB 회원 0건을 확인했다. 가입 뒤 password credential 1건·social 연결 0건, pending cold restart 및 올바른 ID/PW 재로그인의 접근 제한을 확인했다.

관리자에서 12816만 QA 사유로 반려했다. 앱이 사유와 재신청 버튼을 보여 주고 cold restart에도 반려 상태를 유지했다. 학과를 독일어→영어로 수정해 다시 신청했고 pending 화면 및 수정된 관리자 행을 확인했다. 이 회원만 승인하자 foreground 및 cold start에서 승인된 화면으로 돌아왔다. 카카오 연결의 새 동의 화면도 Talk가 먼저 열렸고, 취소는 웹 fallback으로 이어졌지만 기존 native 세션과 미연결 상태는 유지됐다. 카카오 연결 및 해제는 성공했고, native 아이디·이름·이메일은 유지됐다. 해제 뒤 자동 로그인과 실제 ID/PW 로그아웃→재로그인이 통과했고, 프로필 이름 및 미연결 상태를 다시 확인했다. 재연결은 AUTH-QA-12로 실패했다. 연결된 native 회원을 Kakao로 로그아웃→재로그인하는 별도 실기기 사례는 해제 전에 실행하지 않았으며, 재연결 결함으로 추가 검수하지 못했다.

빠른 ADB 로그인 입력에서 일부 ID 글자가 누락된 시도는 자동화 입력 문제로 구분했다. 이후 입력값을 확인하고 문자별로 느리게 입력해 올바른 QA 자격정보의 실제 로그인 성공을 확인했다. 사용자 원래 비밀번호는 사용하지 않았다.

마지막으로 12816을 실제 탈퇴 요청 16으로 접수했다. 즉시 로그아웃·cold restart signed-out·올바른 ID/PW 로그인 차단·저장 접수증 조회가 통과했고, 해당 회원의 refresh 4개가 모두 폐기됐다. Computer Use로 요청 16의 회원 번호를 대조하고 8개 테이블/12건, 보류 및 파일 0건을 검토한 뒤 이 요청만 조기 실행했다. root 및 iOS 요청은 조작하지 않았다. 2026-10-08 23:42 KST 읽기 전용 관측에서 회원·identity·password credential·phone claim·소셜 연결·공급자 자격정보가 모두 0건이었다. 요청은 `processing/database_erased/EXTERNAL_ERASURE_PENDING`, backups/external_data/historical_files는 complete, other_identifiers만 pending이다. 앞선 요청 15도 같은 상태를 유지했다. 새 root 12813의 ID/PW 및 root 권한은 유지됐다. 두 요청 모두 전체 탈퇴 완료로 집계하지 않는다.

## 연결 해제 재현과 수정 검토 지점

동문 승인된 QA12817은 카카오로 가입하고 Apple을 추가 연결한 회원이다. 두 해제 버튼이 활성화된 것을 확인한 다음 각 확인창의 취소와 실제 최종 확인을 수행했다. 취소는 연결을 유지했지만 실제 최종 확인도 연결을 유지했다. `testDirectBothSocialDisconnectOnOwnQA`의 실제 해제 기대 assertion2개가 실패했다. 서버는 해당17.456초 구간에서 아무 요청도 받지 않았고 직전·직후 connections GET200은 정상 수신했다. 마지막 로그인 수단을 서버가 거부한 결과가 아니다.

`ProfileView.swift`의 alert Binding setter는 dismiss 때 `cancelConfirmation`을 호출한다. 최종 확인 버튼은 `Task`로 `confirmDisconnect`를 예약한다. `AuthRepository.swift`의 `confirmDisconnect`는 phase가 `.confirming`일 때만 요청을 보낸다. dismiss가 먼저 phase를 `.idle`로 바꾸면 Task가 요청 전에 return할 수 있다. 최종 확인을 동기적으로 확정한 다음 비동기 삭제를 시작하고, 단순 dismiss·취소가 이미 확정한 동작을 취소하지 않도록 검토해야 한다. 수정 검증에는 두 제공자 각각의 실제 DELETE·서버 상태 변경과, 해제 후 남은 로그인 수단으로 동일 계정 재로그인을 포함해야 한다.

## 탈퇴 완료와 전화번호 재사용

`PhoneHasPendingDeletion`은 원본 회원이 DB에서 제거되면 새 가입을 허용한다. 반면 `IdentifierMatches`는 삭제 문맥의 전화번호를 소유자 구분 없이 전체 텍스트 컬럼에서 검색한다. 새 회원의 정상 `WEO_MEMBER.USR_PHONE` 및 `AUTH_PHONE_CLAIM.CANONICAL_PHONE`이 이전 요청의 `other_identifiers` 완료를 막는다. Apple subject도 원본12817 삭제 뒤 새12818의 정상 APPLE identity·AP 연결에 재사용됐지만 #18 검사에 잡혔다. 원본 회원의 인증 데이터는0이다. 소비·만료된 전화 인증 기록의24시간 보존과 별개이며, 그 이력을 정리해도 새 회원이 있는 동안 차단이 남는다.

수정 검토 시 원본 소유 데이터의 삭제와 정당한 새 소유자의 재사용을 구분해야 한다. 단순 전화번호 매칭을 전부 무시하거나 새 회원 데이터를 삭제하는 방식은 적절하지 않다. 기존 인증 이력 정리, 재사용 claim의 계정 소유자, 파일·증빙의 정당한 보존 범위를 각각 근거로 판정하고 같은 전화번호를 쓰는 새 회원의 정상 로그인도 함께 검증해야 한다. QA를 위해 완료 플래그를 덮어쓰지 않았다.

## 공통 서버의 소셜 재연결

[별도 공통 API 재연결 검수](auth-2026-10-08.md)의 AUTH-QA-12에서 최초 연결·해제·ID/PW 통제는 성공했지만 재연결은 canonical identity unique 충돌로 실패했다. 실제 MariaDB 기대 동작 probe도 정확히 재연결 단계에서 실패했다. iOS에서 최초 연결 성공을 확인해도 재연결까지 통과했다고 확대하지 않는다. iOS native 해제 결함을 수정한 뒤 같은 identity의 재연결·소셜 재로그인을 함께 회귀 검수해야 한다.

## 가입 실패의 서버 경계

[별도 HTTP·MariaDB 검수](auth-20261008/backend-results.md)에서 ID 중복 실패와 소셜 회원 연결 transaction 실패는 신규 서비스 세션을 남기지 않았고 재시도 grant를 보존했다. 회원 생성 commit 뒤 세션 저장 실패는500을 반환하면서 회원은 존재하고 refresh row는0이었다. 같은 폼 재시도는 이미 소비된 전화 grant 때문에 `PHONE_NOT_VERIFIED`로 실패하지만 새 provider 로그인으로 기존 회원 세션을 정상 복구했다. 따라서 가입 실패 때 회원·provider 임시 정보·서비스 세션을 각각 판단해야 한다.

이 서버 장애 검수는 전용 MariaDB와 합성 provider fixture에서 실행했다. 운영 DB에 장애 trigger를 넣거나 실제 Kakao·Apple 서버를 고장 내지는 않았다. iOS에서 이500 뒤 재시도·재로그인 안내의 실제 화면은 미검수이며 보완 검토 대상으로 남긴다.

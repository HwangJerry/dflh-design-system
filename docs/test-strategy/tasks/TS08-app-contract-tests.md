# TS08 — iOS + Android: contract tests that decode the backend Tier 1 goldens with the apps' real DTOs

Repos: dflh-saf-v2-swift (branch `test/ts08-contract-tests`), dflh-saf-v2-kotlin (branch `test/ts08-contract-tests`),
umbrella docs/test-strategy (branch `test/ts08-golden-sync` in the umbrella repo).

Source of truth: dflh-saf-v2/backend/cmd/server/testdata/golden/*.json (14 files, generated by the real router in TS07; see the
"Tier 1 router goldens (TS07)" section of dflh-saf-v2/backend/internal/testsupport/README.md for each file's endpoint and status).
Placeholders in goldens: "<token>", "<timestamp>", "<volatile>", "Bearer <token>". Everything else is the exact response shape.

1. Umbrella: add docs/test-strategy/sync-golden.sh
   - copies the backend golden files into
     iOS  dflh-saf-v2-swift/Tests/DflhSafV2SwiftTests/Fixtures/golden/  and
     Android dflh-saf-v2-kotlin/app/src/test/resources/golden/
     and writes a SOURCE.md there (backend commit hash, date, "do not edit; run sync-golden.sh").
   - `--check` mode: exit 1 and list files if either app copy differs from the backend (no writes).
   - Wire `--check` into docs/test-strategy/test-all.sh as a first "contract-sync" row in the summary.
2. Each app: a test helper that loads a golden and replaces placeholders with values valid for that app's decoders
   (e.g. "<timestamp>" → a fixed ISO-8601/SQL datetime in the exact format the app parses for that field; "<token>" → a synthetic
   string; "<volatile>" → a value of the right JSON type for that key — inspect the DTO). Keep the replacement explicit and small; do not
   loosen production decoders.
3. Each app: one contract test per golden the app actually consumes. Find the real DTO/response type and the real decoding path used by
   the app for that endpoint (iOS: the Codable types used by APIClient/services with the same JSONDecoder configuration;
   Android: the kotlinx.serialization types with AppContainer.defaultJson()/the client's Json). Assert decoding succeeds AND check a few
   meaningful fields (status, verification.status, usrStatus, error code "APP_UPDATE_REQUIRED" and how the app maps a 426, the
   update-policy JSON strings inside settings_public parse via the app's own policy parser, deletion receipt fields the UI shows).
   If an app does not call an endpoint, skip it and list it. If a golden does NOT decode with the app's current DTO, that is a real
   contract bug: do not change the golden or loosen the DTO silently — write the failing test, mark it clearly (XCTSkip/@Ignore with a
   reason referencing the mismatch) and describe the mismatch precisely in the report so it can be decided.
4. Document in each app's docs/operations/UNIT_TESTS.md how contract tests work and that goldens come from sync-golden.sh.

Verify: iOS unit tests (report count; baseline 290) and Android `:app:testDebugUnitTest` (baseline 415); `sync-golden.sh --check` passes
after syncing; `docs/test-strategy/test-all.sh --only ios` and `--only android` pass with the new contract-sync row. Commit in all three
repos on the named branches.

# 앱 UI·UX 결정 사항 (2026-09-30 검토)

iOS·Android 앱의 화면 정의서를 Claude Design에서 함께 검토하며 정한 내용입니다. 구현할 때 이 문서를 명세로 삼고, 화면 모양은 아래 캔버스를 봅니다. 문서와 캔버스가 다르면 **이 문서가 우선**입니다. 캔버스 화면은 정지된 그림이라 동작 규칙을 담지 못하기 때문입니다.

- iOS 캔버스: https://claude.ai/artifact/AoAfsTbFk9Y15n468d7zzX
- Android 캔버스: https://claude.ai/artifact/TD25YcJtR31DpjFPNHNTzb

화면 번호는 `영역 문자 + 번호`입니다(예: iOS `D04`, Android `C18`). 두 앱의 번호가 다를 때는 `iOS X / Android Y`로 적습니다. 캔버스 하나는 파일을 이름순으로 200개까지만 그리므로, 화면을 추가할 때 캔버스마다 200개를 넘기지 않습니다.

상태 표시: **확정** = 사용자가 결정함 · **제안 기본값** = 제가 정한 값이라 구현 전에 바꿀 수 있음 · **미정** = 아직 결정 안 됨.

## 0. 공통 원칙 (모든 화면)

### 0.1 두 플랫폼을 똑같이 (확정)
- 같은 상황에는 두 앱이 같은 화면 구성, 같은 문구, 같은 동작을 씁니다. 다른 것은 플랫폼 관례뿐입니다: 뒤로 가기 아이콘, 알림 창 모양(iOS alert / Android Material dialog), 시트 모양, 버튼 모서리(iOS 8px / Android 12px).

### 0.2 글자 굵기·크기는 디자인 시스템 토큰으로만 (확정)
- 굵기는 `design-system/tokens/design-tokens.json`의 `typography.weight` 네 단계만 씁니다: regular 400, medium 500, semibold 600, bold 700.
- 화면 코드에서 숫자를 직접 쓰지 않고, 공통 텍스트 스타일(iOS `DSTextStyle` / `DSFont`, Android DS 모듈)을 씁니다. 필요한 스타일이 없으면 디자인 시스템에 이름 붙은 스타일을 먼저 추가합니다.
- 이번 검토에서 쓴 스타일
  - 화면 가운데 핵심 메시지: `title` (18, semibold)
  - 상태 화면 제목: `h3` (20, semibold)
  - 설명 문장: `bodySm` (15, regular) 또는 14 regular, `textSecondary` #555555
  - 빈·오류 상태 제목 16 semibold / 설명 14 regular

### 0.3 개발자식 오류를 보여 주지 않음 (확정)
- 금지: 빨간 오류 카드·빨간 오류 문장(불러오기·저장 실패), 서버·네트워크 원문 문장, "다시 시도 / 다시 불러오기 / 다시 검색 / 다시 저장" 버튼, 내부 번호("공지 번호: 812" 등).
- 대신 쓰는 방법

  | 상황 | 동작 |
  |---|---|
  | 목록을 처음부터 못 불러옴 | 차분한 안내 상태(0.4)와 "화면을 아래로 당겨 새로고침해 주세요." 사용자는 당겨서 새로고침합니다. |
  | 목록이 이미 있는데 새로고침 실패 | 아무것도 보여 주지 않고 기존 목록을 유지합니다. |
  | 다음 페이지(추가 로딩) 실패 | 오류 없이 목록 끝의 로딩 표시만 유지하고, 조건이 되면 자동으로 다시 불러옵니다(0.6). |
  | 상세·명함 등 한 건 불러오기 실패 | 회색 한 줄 "…을 불러오지 못했어요. 잠시 후 다시 열어 주세요." (시트·상세처럼 당길 목록이 없을 때) |
  | 펼친 글 본문 실패 | 회색 한 줄 "내용을 불러오지 못했어요. 당겨서 새로고침해 주세요." |
  | 좋아요 실패 | 낙관적으로 바꾼 상태를 조용히 원래대로 되돌립니다. 문구 없음. |
  | 댓글 전송 실패 | 입력한 글을 입력칸에 그대로 남기고 전송 버튼을 다시 누를 수 있게 둡니다. 문구 없음. |
  | 설정 스위치 저장 실패 | 스위치를 이전 상태로 조용히 되돌립니다. 문구 없음. |
  | 폼 저장 실패 | 버튼 위 오류 자리(0.5)에 회색 한 줄 "저장하지 못했어요. 잠시 후 다시 저장해 주세요." 버튼 이름은 그대로("저장"). |
  | 쪽지 전송 실패 (예외) | 쪽지가 사라진 것처럼 보이지 않도록, 보내지 못한 말풍선을 흐리게(투명도 0.6) 하고 그 아래 회색 버튼 한 줄 "보내지 못했어요 · 눌러서 다시 보내기". |
  | 외부 브라우저 열기 실패 | 알림 창 대신 해당 버튼 아래 회색 한 줄 "브라우저를 열지 못했어요. 잠시 후 다시 눌러 주세요." |
- 유지하는 것
  - 사용자가 직접 고칠 수 있는 입력 오류(비밀번호 불일치, 아이디 중복, 사진 5MB 초과, 태그 개수 초과 등)는 보여 줍니다. 색은 빨강 대신 차분한 색(#92400E)을 쓰고, 위치는 0.5 규칙을 따릅니다.
  - 로그아웃·삭제·차단 같은 위험 동작의 빨간 버튼은 그대로 둡니다.
- 로그인·가입 단계처럼 사용자가 행동해야 하는 곳의 오류(예: "아이디 또는 비밀번호가 올바르지 않습니다.")는 0.5의 자리에서 보여 줍니다.

### 0.5 오류 문구 자리는 미리 비워 둠 (확정)
- 로그인·가입·인증·폼 화면에는 주 버튼 바로 위에 오류 문구 자리(최소 높이 36px, 두 줄)를 항상 비워 둡니다. 오류가 나도 버튼·안내 문구가 움직이지 않습니다.
- 오류 문구는 가운데 정렬, 13–15 regular.

### 0.6 당겨서 새로고침과 자동 재시도 (확정 / 수치는 제안 기본값)
- 목록 화면(소식, 알림함, 쪽지함, 대화, 동문, 기부, 내정보)은 모두 당겨서 새로고침을 지원합니다. 화면 예: iOS `E18`, Android `E06`.
- 당기면 그 화면의 첫 페이지를 다시 불러옵니다. 성공하면 목록을 바꾸고, 실패하면 기존 목록(또는 0.4 안내)을 그대로 둡니다.
- 추가 로딩(무한 스크롤): 목록 끝의 로딩 행 "다음 …을 불러오는 중…"(13 regular, #767676, 작은 스피너)만 보여 줍니다. 예: `E07`, `F05`.
  - 실패하면 로딩 행을 유지한 채 **제안 기본값**: 2초, 4초 뒤 자동 재시도(최대 2번 더). 그래도 실패하면 로딩 행을 조용히 숨기고, 사용자가 다시 목록 끝으로 스크롤하거나 당겨서 새로고침하면 다시 시도합니다.

### 0.7 상태 아이콘 (확정)
- 88px 원(#E8E5DF) 안에 24–36px 남색 아이콘: 완료·접수는 체크, 미신청은 서류, 대기는 시계, 확인 불가는 물음표. 반려는 연한 빨강 원(#FEF2F2) 안의 빨간 느낌표.

## C. 회원가입

### C.1 단계 입력 폼의 학과 선택 (제안 → D에서 확정된 부품을 가입에도 적용)
- 기기 기본 드롭다운(iOS `Picker`, Android `DropdownMenu`) 대신, 입력칸 자리에 7개 학과(프랑스어·독일어·일본어·중국어·스페인어·러시아어·영어)를 **2열 선택 버튼**으로 펼칩니다. 버튼 높이 56, 모서리 16. 고른 칸은 남색 2px 테두리 + 체크. 화면 읽기는 `radiogroup` / 선택됨.
- 공통 단계 입력 부품(iOS `DSReverseStepForm`, Android `DSReverseStepForm.kt`)에 선택지를 펼치는 새 방식을 추가합니다. 그러면 아이디 회원가입, 소셜 회원가입, 동문 인증 신청의 학과 단계가 함께 바뀝니다. 기존 드롭다운 부품은 다른 곳에서 쓰므로 남겨 둡니다.
- 화면 예: 동문 인증 `D08`(두 앱). 가입 화면(iOS `C10`, Android `C09`)은 아직 예전 드롭다운 그림이므로, 구현 시 D08 모양을 따릅니다.
- 미정: 프로필 수정의 학과 선택도 같은 방식으로 바꿀지.

### C.2 소셜(카카오·Apple) 회원가입 정보 불러오기 (확정)
- 가입을 시작하면 입력 폼 없이 **전체 화면 로딩**(iOS `C16`, Android `C14`): "카카오 정보를 불러오고 있어요 / 잠시만 기다려 주세요."(iOS는 "가입 정보를…").
- 불러오기에 실패해도 오류를 보여 주지 않고, 같은 로딩 화면에서 문구만 "조금만 더 기다려 주세요 / 연결이 느려 … 다시 불러오고 있어요."로 바꾸고 자동 재시도합니다(iOS `C27`, Android `C17`).
  - 재시도는 **최대 3번**(확정). 간격은 **제안 기본값** 1초, 2초.
  - 로딩 아래 점 세 개로 시도 순서를 은은하게 보여 줍니다(빼도 됨).
- 성공하면 1단계(이름) 화면을 보여 줍니다.
- 3번 모두 실패하면 안내 창(iOS `C28`, Android `C25`):
  - 제목 "회원가입에 문제가 생겼어요"
  - 내용 "카카오 정보를 불러오지 못해 지금은 가입을 진행할 수 없어요. 오픈채팅으로 문의를 남겨 주시면 확인 후 도와드릴게요."(iOS Apple은 "계정 정보를…")
  - 버튼 "닫기"(→ 로그인 첫 화면, 제안 기본값) / "오픈채팅 문의"(→ 로그인 도움말과 같은 카카오 오픈채팅 주소, 공개 설정 값)
- 빼는 것: "카카오 정보 없이도 가입할 수 있습니다.", "카카오 정보 다시 불러오기".

### C.3 소셜 회원가입 마지막 단계 = 프로필 사진 (확정)
- 단계 수 7 → **8**. 졸업연도 다음, 최종 확인(동의) 앞에 프로필 사진 단계를 둡니다. 기존 단계에 붙어 있던 구석의 작은 사진은 뺍니다.
- **별도 페이지**로 구성합니다. 앞 단계 입력 카드 목록은 보여 주지 않습니다.
  - 머리글: 뒤로, "회원가입", "8 / 8", 안내 "마지막 단계예요. 이것만 정하면 입력이 끝나요.", 진행 막대 100%
  - 화면 세로 가운데: 140px 원형 사진, 질문 "이 사진을 프로필 사진으로 사용할까요?"(20 semibold), 설명(14 regular)
  - 사진 영역 자체가 버튼입니다. 오른쪽 아래에 남색 원 편집(연필) 아이콘을 둡니다. 누르면 사진첩(iOS PhotosPicker, Android Photo Picker)을 엽니다.
  - 버튼은 **"이 사진 사용" 하나만** 화면 아래에 둡니다. "다른 사진 선택", "다시 선택", "사진 없이 계속" 버튼은 두지 않습니다. "마지막 단계 · 프로필 사진" 표시도 두지 않습니다.
- 경우별 화면과 동작

  | 경우 | iOS | Android | 동작 |
  |---|---|---|---|
  | 소셜 계정 사진 있음 | C20 | C18 | 설명 "카카오 계정에서 가져온 사진입니다. 사진을 누르면 다른 사진으로 바꿀 수 있어요." |
  | 소셜 계정 사진 없음 | C21 | C19 | 이름 첫 글자 원. 질문 "프로필 사진을 등록할까요?" 설명 "사진을 눌러 사진을 고를 수 있어요. 가입 후 내정보에서도 바꿀 수 있어요." |
  | 새 사진 올리는 중 | C22 | C20 | 사진 위 로딩, 사진·버튼 모두 누를 수 없음 |
  | 새 사진으로 교체됨 | C23 | C21 | "이 사진 사용"을 누르면 확인 없이 다음(최종 확인)으로 |
  | 올리기 실패 | C24 | C22 | 원래 사진 유지, 설명 아래 한 줄 "사진을 올리지 못했어요. 다시 시도해 주세요." |

- 서버: 가입 중 사진 올리기는 기존 `POST /api/auth/social/link/photo`(소셜 연동 토큰 필요, 5MB)를 씁니다. 성공하면 가입 요청의 `profileImageUrl`이 새 사진이 됩니다. "사진 없이"는 가입 요청의 `profileImageUrl`을 비워서 보냅니다(서버 처리 확인 필요).
- 최종 확인 화면에 "프로필 사진 / 카카오 사진 사용"(또는 "새 사진", "사진 없음") 칸을 추가합니다(iOS `C19`).

## D. 동문 인증 — 확정

### D.1 상태 화면 공통 틀 (D01–D06, D12, D13)
- 머리글은 제목 "동문 인증"만 둡니다. **← 뒤로 가기 없음**(예전에는 누르면 로그아웃됨).
- 화면 가운데: 상태 아이콘(0.7), 제목(`h3` 20 semibold), 설명(15 regular), 필요하면 카드
- 화면 아래: 오류 문구 자리(0.5) → 주 버튼(필요할 때만) → 작은 글자 링크 "다른 계정으로 로그인 | 계정 삭제 요청"
- "다른 계정으로 로그인"은 로그아웃 후 로그인 첫 화면으로 갑니다.

| 번호 | 상태 (서버 값) | 아이콘 | 제목 / 설명 | 주 버튼 |
|---|---|---|---|---|
| D01 | 미신청 `unsubmitted` | 서류 | 동문 인증이 필요해요 / 졸업연도·기수·학과를 입력해 동문 인증을 신청해 주세요. | 인증 신청하기 |
| D02 | 대기 `pending` **및 재승인 대기 `reapproval_pending`** | 시계 | 동문 인증을 확인하고 있어요 / 신청이 접수되었어요. 승인되면 알림으로 알려 드릴게요. | 없음 |
| D03 | D02 + 기기 알림 권한 꺼짐 | 시계 | D02와 같음 + 카드 "알림이 꺼져 있어요 / 승인 결과를 바로 받으려면 알림을 켜 주세요. [알림 켜기]" | 없음 |
| D04 | 반려 `rejected` | 빨간 느낌표 | 신청이 반려되었어요 / 사유를 확인하고 정보를 고쳐 다시 신청해 주세요. + **반려 사유 카드**(사유가 없으면 "반려 사유가 등록되지 않았습니다. 담당자에게 문의해 주세요.") | 정보 수정 후 재신청 |
| D06 | 확인 불가 | 물음표 | 인증 상태를 확인할 수 없어요 / 다시 로그인하면 상태를 새로 불러와요. | 다시 로그인 |

- 재승인 대기를 따로 보여 주지 않습니다. 서버의 `reapproval_pending`도 D02 화면으로 보여 줍니다(D05 삭제).
- 예전의 "신청 반려 사유" 확인 창은 없앱니다(D04에 바로 표시).
- 대기 화면은 화면이 보일 때·앱으로 돌아올 때·인증 결과 푸시를 받을 때 상태를 다시 불러옵니다(기존 동작 유지).
- D03의 [알림 켜기]: iOS는 설정 앱의 앱 알림 화면, Android는 앱 알림 설정(권한 요청이 가능하면 요청) 화면을 엽니다.

### D.2 인증 신청 폼 (D07–D10)
- D07 1/3 졸업연도 → 2/3 기수 → D08 3/3 학과(C.1의 2열 선택) → 확인 단계
- 뒤로 가기는 "인증 상태로 돌아가기"입니다(로그아웃 아님).
- **재신청(D09)**: 반려 후 "정보 수정 후 재신청"을 누르면, 처음부터 한 칸씩 입력하지 않고 이전에 낸 값이 채워진 **확인 단계**로 바로 엽니다. 위에 반려 사유 카드를 보여 주고, 틀린 칸만 "수정"한 뒤 "수정 후 재신청".
- D10 저장 실패: 버튼 위 오류 자리에 "신청을 저장하지 못했어요. 잠시 후 다시 시도해 주세요."

### D.3 가입 직후 자동 인증 신청 (D11, D12)
- 가입을 마치면 로딩 화면 "동문 인증을 신청하고 있어요 / 잠시만 기다려 주세요."(D11)에서 인증 신청을 보냅니다.

### G.2 쪽지 새로 보내기 — 2단계, 여러 명 (확정)
- 전체 화면(탭 바 없음). 공통 머리글: 뒤로/닫기, "쪽지 새로 보내기", 단계 "1 / 2"·"2 / 2", 진행 막대.
- **1단계 받는 사람 선택**
  - 안내 "받는 사람을 골라 주세요. 여러 명을 고를 수 있어요."
  - 검색칸 "이름으로 동문 검색"(지우기 버튼, 입력 후 잠시 뒤 검색)
  - 고른 사람은 검색칸 아래 이름표(남색 테두리 칩, × 로 빼기)로 모입니다. 다른 검색어로 찾아도 이름표는 유지됩니다.
  - 결과 행: 40px 아바타, 이름(15 semibold), "N기 · 학과", "직종 · 직무", 오른쪽 체크박스(24px, 선택 시 남색 채움)
  - 아래 고정 버튼 "다음": 0명이면 비활성, 고르면 "다음 (N명)"
  - 본인은 목록에서 뺍니다(예전 검증 "본인에게는 쪽지를 보낼 수 없습니다."). 차단한 사람도 선택할 수 없게 합니다(제안 기본값).
  - 받는 사람 최대 인원: **미정**(제안 기본값 20명).
- **2단계 쪽지 작성**
  - 안내 "보낼 내용을 입력해 주세요."
  - 받는 사람 요약 카드 "받는 사람 N명 / 김하늘, 이서준 [변경]"(변경 → 1단계, 선택 유지)
  - 내용 입력칸(최소 높이 약 220, 모서리 16), "쪽지 내용을 입력하세요", 글자 수 "N/1000"
  - 안내 "각 동문에게 1:1 쪽지로 보내져요."
  - 아래 고정 버튼 "쪽지 보내기"(내용이 비면 비활성), 보내는 중에는 스피너 + "보내는 중…"
- **보낸 뒤**: 한 명이면 그 사람과의 대화로, 여러 명이면 쪽지 목록으로 갑니다.
- **일부 실패** iOS G23 / Android G22: 버튼 위 회색 한 줄 "이서준 동문에게는 보내지 못했어요." + 글자 버튼 "다시 보내기"(실패한 사람에게만). 주 버튼은 "완료".
- 서버: 쪽지 API는 1:1만 있으므로 받는 사람마다 `POST` 한 번씩 보냅니다(각각 멱등 키). 여러 명 한 번에 보내는 API가 필요하면 별도 결정.
- 화면: iOS G16 처음 · G17 검색 중 · G18 2명 선택 · G19 결과 없음 · G21 검색 실패 · G20 작성 · G22 보내는 중 · G23 일부 실패 / Android G15 처음 · G20 검색 중 · G16 2명 선택 · G17 결과 없음 · G19 검색 실패 · G18 작성 · G21 보내는 중 · G22 일부 실패.

- 새로고침 실패 문구(iOS J04의 빨간 "프로필 정보를 새로 가져오지 못했습니다.") 삭제.

## 검토 중 발견했지만 아직 다루지 않은 것 (미정)
- iOS 알림 권한을 앱 실행 즉시(로그인 전) 요청합니다(A02). Android는 로그인 후 설명과 함께 요청합니다.
- 댓글 삭제(두 앱)와 Android 대화 차단이 확인 없이 바로 실행됩니다.
- iOS "개인정보 설정"(J23)의 스위치가 저장되지 않습니다. Android는 같은 행이 프로필 수정으로 갑니다.
- iOS 댓글 신고 안내의 오타 "선택한 댓글와".
- 쪽지 안읽음 배지 상한이 다릅니다(iOS 99+, Android 9+).
- 기부하기가 iOS는 기본 브라우저, Android는 앱 안 웹 시트입니다.
- 계정 삭제 처리 현황이 iOS는 웹 시트, Android는 앱 화면(K)입니다.

## 구현 순서 제안
1. 디자인 시스템: 0.2 텍스트 스타일 점검, 0.4 빈·오류 안내 부품, 0.5 오류 자리 부품, 단계 폼의 2열 선택 방식(C.1), 쪽지 체크박스·이름표 칩.
2. 공통 동작: 당겨서 새로고침·추가 로딩 재시도(0.6), 좋아요 되돌리기, 설정 되돌리기.
3. 화면: B 로그인 → D 동문 인증 → C 회원가입(C.2–C.4) → E·F·G·H·I·J 오류·빈 화면 → G.2 새 쪽지.
4. 영역마다 두 앱을 같이 구현하고, 디자인 시스템 검증(`npm run verify-ios-design-system`, `verify-android-design-system`, `verify-design-system`)과 각 앱 테스트를 통과시킵니다.
